# DIgit UI audit and improvement plan

## Scope and architecture
Preserve redesign of the current browser simulation, not a native app migration. `core.js` owns image rendering and capture state, `ui.js` binds DOM and session state, `view.html` owns markup/style, and `build.cjs` emits the runnable page and inline fragment. No package manifest, lint configuration, routes, analytics, or native target exists. Keep the existing wordmark, camera selector, settings order, rendering, and save model.

## Rendered baseline
Inspected Chrome at 375px (output/playwright/before.png). Full-screen imagery and three bottom controls work well. Existing colors are charcoal, warm silver, and muted gold; system sans with mono exposure values. Problems: 10px panel labels, 34px selects, tiny Done targets, landscape gallery crops of portrait captures, limited keyboard focus feedback, and visually disconnected comparison/file tools. Save recovery sits only in development controls. Existing motion is a shutter press (variance 4, motion 2, density 4).

## Design constraints
Design variance 4, motion intensity 3, visual density 3. Native system font appropriate for the intended iPhone product. No new framework, decorative images, marketing sections, or icon dependency. Camera imagery is the actual interactive content. UI UX search suggested minimalism but its oversized marketing typography is inappropriate; apply its touch-target and keyboard guidance. Frontend taste's native-mobile exclusion and unrelated landing-page checks are marked not applicable.

## Verification results
17 core tests pass. Chrome browser flow check passes: capture, settings, gallery empty/populated states, permission denial, write failure, retry, modeled hardware, comparison, local file, lighting, and focus. Captured five widths (320, 375, 768, 1024, 1440) in light and dark with no horizontal overflow or JavaScript errors. Inspected finished mobile options and phone/desktop light/dark screenshots. Settings controls measured at least 44px tall. Fixed focus loss when a successful retry removes its own gallery button. ESLint, JavaScript syntax checks, and prototype build pass. Camera panel uses internal scrolling on smaller phones to keep the shutter reachable. Real iPhone camera, Photos, and hardware integration remain outside this browser audit.
